# Agent Guide

## Project Shape

- This is a build-free static PWA: the repository runs as is, including under a subpath. The deploy runs one optional step, `npm run build:site` ([scripts/build-site.js](scripts/build-site.js)), which writes `dist/` with the scripts minified (top-level names kept) and without `data/catalog.json`; CI smoke-tests that output too. See [README.md](README.md) for the full rationale and checks.
- [index.html](index.html) owns the shipped markup and classic inline application JavaScript.
- [assets/app.css](assets/app.css) owns layout, base styles, and theme overrides.
- [assets/accessibility.css](assets/accessibility.css) owns focus, skip-link, reduced-motion, and mobile performance styles.
- [assets/accessibility.js](assets/accessibility.js) owns keyboard and ARIA behavior for dynamic strategy rows.
- [data/catalog.json](data/catalog.json) is the catalogue's source of truth, published to the database when it merges to `main` (the Publish catalogue workflow, `publish_catalog_with_key`) or from the admin page (`publish_catalog`); the app reads it through `get_catalog()` and the file is never deployed. [data/catalog.js](data/catalog.js) only restores the browser's saved copy into `CATALOG_DATA` before the first refresh. Referral links never reach the browser: `launchUrlFor()` sends OPEN through the `go` edge function for platforms flagged `hasReferral`. A Pro account's own link (the edit sheet's referral field, mirrored to `member_links`) comes first; a platform imported from a friend's shared list carries its `shareCode` and adds `&via=<launch token>` so the database can serve the sharer's link when both hold Pro (see README, *Pro referrals and shared lists*).
- [sw.js](sw.js) owns offline caching and same-origin network behavior.

## Working Rules

- Preserve classic scripts, global functions, inline `onclick` handlers, and the current script-loading order unless deliberately migrating the whole architecture.
- Use two-space indentation, semicolons, and existing naming patterns.
- Keep local URLs relative; the app may run under a GitHub Pages subpath.
- Treat localStorage keys and persisted state as public contracts. Add migration logic before changing a key.
- Do not add frameworks, bundlers, or unrelated refactors. The one runtime exception already in place is `supabase-js`, loaded via CDN `<script src>` (see Cloud Sync below) the same way Google Fonts already is - no bundler, nothing to `npm install` to run the app. The only dev dependency is `terser`, used by the deploy step alone. The second, agreed for the landing intro: three.js, vendored (minified, unmodified) in `assets/vendor/three/` and loaded only by the WebGL intro (`assets/intro3d/intro.mjs` and its other games, `assets/intro3d/wheel.mjs`, `assets/intro3d/plinko.mjs`, `assets/intro3d/blackjack.mjs` and `assets/intro3d/slots.mjs`) and the homes it flies into (`assets/intro3d/table.mjs`, `assets/intro3d/study.mjs`, `assets/intro3d/arcade.mjs` and `assets/intro3d/slaughter.mjs`, which also use the addons' `CSS3DRenderer` for the page elements laid in the scene) through a dynamic `import()` - and, the same way, by Obsidian Ledger's orrery (`assets/intro3d/orrery.mjs`, its Lounge payout, fetched the first time it plays, and the study's centrepiece; and Neon Grid's moonrise, `assets/intro3d/moonrise.mjs`, and West Texas Gore Fest's inferno, `assets/intro3d/inferno.mjs`, likewise) - see `assets/vendor/three/README.md` for the version and how to update it. Don't add further dependencies beyond that without deliberate discussion.
- Catalog edits must preserve required fields and optional metadata; tracked user copies are persisted separately from the catalog.
- Dynamic interactive rows must retain the existing accessibility behavior.
- The landing's table is built before the gate: `createIntro({ onScene })` hands the shot's scene over as soon as it stands (before its shaders compile), and `prepTable(look)` builds the table and the dealer's rig into it on the next turn, under that compile (its module is fetched beside the shot's; its own warm-up goes through the shot's api once that exists); and the seal reads TAP TO ROLL only once the table reports built (`prepareTable({ onBuilt })`, after its warm-up and the dealer's prime; capped by `TABLE_WAIT`, 12 s) - a phone showed the build as held frames when it ran under the shot, and a still seal hides it; the shot's next two quality steps are prepared under the seal too (`api.prepSteps(2)`: their shaders compiled and linked, so a step in the shot is a switch, not a compile), and the step each game's shot settles on is remembered per device (`ROLL_QUALITY_KEY`; `createIntro({ quality: 0..3 })` starts there, climbing a step after three clean shots) so a phone that stepped down once never steps mid-shot again; `prepareTable({ showWhen })` keeps the table hidden, lamp off, until the shot ends. The dealer's rig goes with it: his canvas is a second WebGL context (`buildRig()` in `table.mjs` - the cards are page elements over the table's canvas, and a hand must draw over the cards it deals), built, compiled and drawn once unseen under the gate when `prepareTable({ gl })` is given the renderer (`api.peek()`), so `fly()` only attaches it. While he waits, his canvas is not drawn again (`drawArms()` skips a frame that would be the one on it - `armsStill()`; the life in his fingers and lights holds with it, `liveT`; nothing of him in view, the canvas is cleared once and hidden), so a card lifted or spun at rest costs the table's frame alone; `rollTable.frames` counts each canvas's frames in the lab. `?perf` overlays the shot-to-seat timings (also logged as `[dro perf]`); read those from a phone before changing this path.
- The homes' music is `assets/intro3d/music.mjs` (plain WebAudio, no three.js): per piece, three 16-bar loops - Base, Main, Lift - at `assets/intro3d/rare/music/`, cut to the same sample length and started on one clock, so a layer change is a two-bar crossfade and never a restart. Two pieces (`PIECES`): `card` (R x R, 119.73 BPM in D, `rxr-*.mp3`) for the card table `study` (Sifsi, 82.12 BPM in F minor, `sifsi-*.mp3`; Base is the Remix's stems without drums or vocals) for the study, and `wtgf` (75 BPM in E minor, `wtgf-*.mp3`; Base is Main's stems without drums or percussion, with the kick-locked sidechain duck on bass and guitar undone by a bar-periodic gain curve) for West Texas Gore Fest's slaughter floor, and `valley` (132.16 BPM, `valley-*.mp3`: the owner's Suno piece for Burin & Brimstone - a groove-metal procession over a psytrance floor; Base is bass, synth, keys, brass and the rest of the bed, Main adds drums and percussion, Lift the guitar; its 16 bars are cut from the track's second peak) for the valley; the other homes are quiet. One room has a piece of its own: `burin` (132.62 BPM, `burin-*.mp3`, the same track's first peak, same layering) plays in Burin & Brimstone's Lounge - `ROOM_PIECES` maps a look to a piece, `roomMusicSync()` starts it when the look is worn with music on and no home seated (after `applyTheme`, after a seat is left, when music is turned on), the room's collect lifts it (`window.roomMusicLift`), and Motion off holds it on Base. `index.html` drives it (`rollMusicStart(dest, roomLook)` picks the piece by home via `MUSIC_PIECES` or by look via `ROOM_PIECES`, and restarts on a home change; `rollMusic.touch()` / `rollMusic.lift()`): started by the tap that takes the seat, Main while you are at the cards or the ledger, Base when a sheet is over the table or nothing has happened for 20 s, Lift on a collect or an S-tier card lifted. Started under the landing's shot and carried into the seat. A change of home crossfades one piece into the next (equal-power, `MUSIC_XFADE`, 4 s): the outgoing piece plays on until the incoming one has loaded, both play on one shared AudioContext (so a piece started after an await, outside the tap, is not held silent), and leaving a seat parks the piece for `MUSIC_PARK_MS` so the next home can take it up - the same piece plays on, another fades in over it, a home without one lets it fade away (`rollMusicLetGo`; `rollMusicStop` is the quick fade for Settings). A replacement loop must keep its piece's tempo, key and exact sample count, or all three must change together; takes from different generations are not the same tempo until stretched to one (R x R's three were 119.16 / 119.73 / 119.66 before; Sifsi's 82.12 / 83.24 / 82.40; WTGF's 75.000 / 75.038, Hi also 22 ms early on the kick until shifted). Suno stems summed can pass full scale: set the level, then limit circularly (over three copies, keeping the middle) so the seam is treated like any bar.

## Validation

Run from the repository root:

```bash
npm run check
npm run check:syntax
npm run check:refs
npm run check:catalog
npm run test:smoke                 # browser flows against a fake Supabase
npm ci && npm run build:site && SMOKE_ROOT=dist npm run test:smoke
```

The authoritative script definitions are in [package.json](package.json), and CI runs the full check through [.github/workflows/checks.yml](.github/workflows/checks.yml). Use the narrowest relevant check first, then the full suite for cross-file changes.

## Theme Work

- Theme definitions live in the inline `THEMES` object in [index.html](index.html). Object order is picker order.
- Theme variables, `bodyBg`, and browser `theme-color` are applied through the existing theme engine and exposed via `data-theme`.
- Skins come in pairs: a **visualized** skin and its **muted** pairing - same colours, different effects. A visualized skin names its pairing in `look` (it wears that theme's palette and every `[data-theme="<look>"]` rule) and the table the landing flies into in `table` (its home; see `assets/intro3d/table.mjs`). `applyTheme()` sets `data-theme` to the look and `data-skin` to the skin itself, so rules that are the visualized skin's own effects (for Refinement × Realization in its pages: the sweep on the gold - its drifting three-tone mesh was retired 2026-10-18, so its pages are Executive Lounge's room) are scoped `[data-skin="<id>"]`, while the room both share - for Executive Lounge: black cards on brushed obsidian, one slow swaying light, a little gold dust - is `[data-theme="<look>"]`. The muted pairing is the quiet, readable take of the same room. Refinement × Realization (`refinement`, the default) / `executive` (once called Executive Lounge; the stylesheet's `[data-theme="executive"]` rules and this guide still name its room so) is the first pair. To the person using it a pair is one skin: the Theme picker (`renderThemeUI()`) lists the visualized skin only, lit while either half is on, with its levels under it; tapping it while on either half goes to the levels (`pickSkin()`), and from another skin it goes to the visualized one. The levels are chosen in Settings' block above the picker, which carries the skin's name (see How much show below); ids and stored `almanac_theme_v1` values are unchanged. Everyone was moved onto it once when it became the default (the `almanac_skin_rxr_v1` flag, set by the pre-paint bootstrap); a skin picked after that is kept. The bootstrap at the top of `index.html` mirrors the look table and must be kept in step.
- A skin's home is named by `table` in THEMES and flown into after the shot: the card table (`card`, `assets/intro3d/table.mjs`, Refinement × Realization's) the study (`study`, `assets/intro3d/study.mjs`, Obsidian Ledger's) the arcade (`arcade`, `assets/intro3d/arcade.mjs`, Neon Grid's) or the séance room (`seance`, `assets/intro3d/seance-room.mjs`, Dead Channel's). `ROLL_DESTS` in `index.html` maps each to its module; every one exports `prepareTable()` with the same contract (built into the intro's scene, warmed, then `fly(world, opts)` returns the controller), and `rollSetHome()` leaves one home for another when the skin changes. Out of body (`rollDrift(dest)` and its panel, `rollDriftOpen()`): a ghost button over any home drifts you to another in the same room - the new home is built into the scene, hidden and warmed while you are still seated, the old controller lets go, the room goes back to how the shot left it (`rollRoomState()` / `rollRoomRestore()`: lights, environment, lens, bloom, exposure - each home dims the house to suit itself), and the new home's own `fly()` takes the camera from the old chair to its own; the old set is removed once you land. A visit changes nothing else: "Sit here" (`rollDriftSit()`) makes that home's skin yours. So every home's `fly()` must start from wherever the camera is, and each controller's `dispose()` must hand the camera and page back. Settings' "Play the Landing Now" (`replayLanding()`) leaves the seat and plays the shot again, no reload. The landing on open is a choice in Settings (`rollLandingMode()`, stored under `almanac_show_landing`: `'daily'` the shot on the first open of the day, stamped in `almanac_landing_seen_v1` as the choice is made at boot, and the seat taken directly after; `'false'` never; anything else - the default - `'true'`, every open). Every open became the default on 2026-10-05 and everyone on once a day was moved onto it once (`almanac_landing_every_v1`); a choice made in Settings after that is kept. A backup carries the choice with `landingEvery: true`; one without it (from before the switch) has its once a day read as that same move, and a restored choice sets the flag so it stands. A tap on the felt or Enter before the deal is done jumps the table's clock to the dealt frame (`skipAhead` in table.mjs). `?dest=card` / `?dest=study` / `?dest=arcade` / `?dest=seance` picks one under any skin; `?dest=none` keeps the classic landing. The felt and trim pickers are the card table's alone: another home's shot keeps the house's black and gold. The intro's sound is on unless the speaker switched it off (`almanac_intro_sound`, reset to on once by `almanac_intro_sound_on_v1`); browsers hold a page silent until its first tap or key, so that tap starts it (`createIntro()` in `assets/intro3d/intro.mjs`).
- Every home is grounded and lit the same way (`tableKit` in `assets/intro3d/table.mjs`). Contact: `contactShadow()` has two parts, as a real one does - a near-black core right at the footprint's edge, where no light gets under, and a soft spread round it - so use it for anything standing on a surface rather than a single soft blob. Cards are page elements drawn over the canvas, so the lamp's shadow on the felt can never fall on a card underneath: a card lying flat also carries its contact in its own plane (`.r3t-card:not(.r3t-lifted) .r3t-face`), gone once it lifts. Light: seated, the room's even light (the intro's environment) settles back to `ROOM_ENV` of itself over the fly-in's second half, so the home's own lamp is what pools (each home sets `scene.environmentIntensity` in its `update()` and puts it back in `dispose()`; the séance room goes lower still, a room lit by candles). A card lifted to you is held, not pinned to the glass: tipped back and turned a touch (`HELD`), your drag turning it from there. The phone (`.r3t-phone`) sits low in the corner, clear of each home's clock, footer and wordmark - check all four homes in portrait when moving it.
- A card's face (`cardHTML()` in `assets/intro3d/table.mjs`, the same in every home) is printed as a casino deck's ace: cream linen-finish stock (black for S), the tier letter and its pip at two corners, one great pip in the middle with the platform's initials knocked out of it and an open line just inside its edge, the name in red, the day's value in black between two short rules. The tier shows in the frame (oxblood double rule for D/C, bronze foil for B, platinum for A, gold foil and filigree on black for S). The pips are drawn paths (`PIPS`), not font glyphs (some platforms turn the red suits into emoji). The great pip is an SVG drawn as an `<img>` with its colours set in `cardHTML()` (keep them matching `--stock` / `--ink` in the stylesheet): SVG shapes moved by their own `transform`, drawn inline, land out of place once the card is laid in 3D. The linen (`.r3t-linen`) lies over the print, as an emboss is pressed through the ink. A foil frame is masked to its border so the stock shows inside it; the filigree mask image is greyscale, so masks using it read luminance (`mask-mode: luminance`).
- With motion off (`html[data-motion="off"]`), a visualized skin's pages must be exactly its muted pairing's, and its table is entered with `reduced: true` (a cut to the seat, the cards already dealt, the dealer up at rest, nothing moving after - no gestures).
- The landing's shot is one of the games in `GAMES` (`assets/intro3d/intro.mjs`), drawn alike each launch (`pickGame()`; `?game=dice` / `?game=wheel` / `?game=plinko` / `?game=blackjack` / `?game=slots` fixes one, and the lab panel lists them); straight to the seat (the daily landing already seen, a skin switch) it is the dice, the shot every home's fly-in was laid out from. The dice are intro.mjs's own; every other game is a module beside it (`assets/intro3d/wheel.mjs`, `assets/intro3d/plinko.mjs`, `assets/intro3d/blackjack.mjs` and `assets/intro3d/slots.mjs`) exporting `makeGame(ctx)`, which builds its pieces into the same room once the set and its lights stand (every light it will use with them, at build) and hands the shot its `plan` (its own `warp`, `wallW` its slow moment, `restW`, `callW`, `revealW`, `endW`, `values`, `call`), `camera()` (its path, the float up under the ceiling included, written into the shot's eye/aim arrays), `gleamAt(t)`, `stage(t, { w, rate, gleam })` (its pieces, its own house lights, back `{ burst, dust }` for the bloom and the dust), `callAt(w)` (where its call sits; `callScrim: true` puts a soft shade of the room behind it, for a call that can land over pale pieces, an optional `callScrimAt(w)` scales that shade through the shot, and an optional `callAlphaAt(w)` takes the call itself out for a moment, such as a pan it would otherwise cross; the call is always kept below the tier's caption), `sfx` (real seconds; the `Sound` class has its kinds), `warmAt` (the turns drawn unseen before the first frame), `silence` (real seconds, for a tier that cuts the room dead), `tierNames` (where the call already names the tier, the caption gives the odds alone), an optional `tierOdds` (odds that replace the draw's in the caption, for a game that folds a tier into another), `goldCall` (its hardways called in the house gold, not the dice's platinum), `moments` (for the lab) and `dispose()`. The set, the resolution, the post, the sound, the quality steps, the overlays and the handover to the homes are shared and stay in intro.mjs. The wheel is a Big Six money wheel standing beyond the back rail under its own lamp (`HUB`), only there for its own game: 54 pockets (`POCKETS`), the spin integrated before the first frame (`makeSpin()`: the bearing's drag, the energy each peg costs the wheel lifting the clapper, and the pull chosen by bisection so the wheel rests on the pocket the tier drew - a one, two, five or ten; The Twenty; The Joker, the joker or the house pocket, which lights and sends gold round the pegs; The Peg, the clapper stopped dead against a peg, the room silent); time slows round the last peg (`makeWarp`, exported); the clapper is a leather strap as deep as the pegs stand, pushed aside by each peg and bending round it (`clapperAt()`, `strapShape()`, `bendStrap()`), so a peg is never through it. The plinko is a walnut-and-brass cabinet to the wheel's right (`CAB`), the same way only there for its own game: a brass chute at the top, where the house chip (oxblood clay, brass-bound) waits on a brass lever, eight rows of pins fanning out to nine lacquered buckets with the house numerals (`BUCKETS`: the edges pay twenty, the house's bucket dead centre); the drop is a 2D simulation run before the first frame (`dropSim()`: the chip between the board and its glass, the pins, the fanned rails, the buckets' walls and floor; a graze held off without a bounce, so a chip rolls off a pin as one does), the chip's place on the lever and the lever's nudge searched until it lands in the bucket the tier drew (a ten, five or two; The Twenty, an edge bucket; The House, the centre bucket, whose brass floor is a trap that drops the chip into light while the pins chase gold up the board; The Pin, the chip come down square on a pin and balanced there, scripted from that hit, the room silent); time slows round the last pin; the lens rides down with the chip. The blackjack is a salon table of the house's beyond the back rail, left of the wheel, under its own pendant (`BJ`), only there for its own game, dealt by the card table's own machine: the table, the shoe, the discard, the port, the chips' clay and the whole dealer rig come from `assets/intro3d/table.mjs` through its `dealerKit` export (`buildCardTable()` takes `opts.rail` and `opts.mark` for its own rail and its own print, `LETTERS`), and the rig is posed the way the home's is (the planner's moves, the hand-to-hand toss, the pitch, the push-turn, the trailing wobble, the IK) - change the rig there and both follow. The machine rises out of its port and deals one hand off the shoe (`dealFor()`: your two, its up card and hole card, and a third when it draws), each card thrown and pitched or laid and pushed over; the tier is the hand (`TIER_NAMES`): a winning hand (your nineteen or twenty over its seventeen or eighteen, or it draws and busts); Blackjack (an ace and a ten-card, the dealer showing two to nine, so it is paid at once and the hole card stays down); The Black Jack (the ace of spades and a black jack, the felt's print lit gold along its letters, the machine's circuits lit, the bell); the draw's fourth tier, edge, is not played here - the natural is the game's rare hand, so intro.mjs folds it into The Black Jack for the blackjack (`TIER_FOLDS`), and the game's `tierOdds` gives the caption the folded 2%. In a standard hand or a Blackjack the table is cleared after the call: one drop slot (`SLOT`, `SWP`) stands in the cloth in front of the machine's port: a raised bevelled bezel (a low ramp for the near lip, which the cards tip over) in the metal of the trim chosen in Settings (`SLOT_METAL`; `setTrim()` on the game's contract is called by the intro's own `setTrim()`), a glint on it when shut; its two dark leaves draw back off a black well while the machine lays its hand flat across its own cards and washes them together in a slow circle, as dominoes are washed (`washPlan()`, `WASH`: the cards follow the hand's circle into one pile), pushes the pile to the near lip and lifts clear, the cards tipping over the lip one a beat apart, short edge first, and yours - which it cannot reach - slide across the cloth after them by themselves; it shuts, the machine sinks into its port, and the table's lettering is let go quiet as the page's own end card takes the screen. The call is set on a dark gold-framed plate hung at the top of the screen (`callPlate: true`), never over the white machine - and on a wide, short screen (a phone on its side: width over 1.4 x height) in the left margin of the felt instead, narrower, its caption pill stacked above it (set inline from intro.mjs, cleared again when the screen is tall), so the dealer's hands and cards are never under it; the caption pill is near-opaque so a bright arm does not show through - and the tier's caption fades as the end card comes up (`badgeFades: true`). The slot melts away as the end card arrives, and the end card takes the plates' type for every game's shot in the house look (wide-tracked Georgia capitals in gold, in app.css under `[data-theme="executive"] .landing-screen.roll-webgl`; the light felts keep their dark ink and other skins keep their own title). The shot is always the 3D one: a slow load is waited for (a tap meanwhile skips the shot to its end once built), and only a shot that cannot be made (no WebGL 2, a module that will not load, a build that throws) falls back to the CSS intro. The blackjack's cloth wears a tiling nap shade map (short crossing fibres and worn paths - the paths drawn sharp on one layer and blurred in a single filtered draw, never a filter per stroke - set at build over the card table's felt, with a tighter sheen) and the dealer's hands a ceramic knuckle bridge, a ball at each finger root, webs between the fingers, tapered phalanges whose rounded ends are centred on the joints so neighbours share a joint sphere (`tapered()`: no waist, no gap), each finger its own (a spec table in `buildDealerHand()`: where its knuckle stands on the arc, its length, its three phalanges' shares, its girth - a real finger's, about a quarter of the knuckles' width - and a short gold cap where the print is, never a ball, its rest yaw and a relaxed arch the grip adds to - the middle longest, the little finger short with a stub middle phalanx), a thumb jointed twice (a ceramic ball in a gold bezel let into the thenar pad, and a graphite hinge pin at its knuckle hung with the last phalanx, `thumbTip`, which closes on the grip), and a clean glazed back with one gold keyline panel (no circuit print on the palm) (`buildDealerHand()` in table.mjs; the home's hands too). The dealer's arms and column carry their circuit print cut into the glaze under glass (`circuitTex()` in table.mjs: a smoked seam by day, a negative emboss for the cut, glossy not metal, and the emissive map drawn as stacked wide-to-narrow strokes so the light is diffuse, as if it came up from under the ceramic; the pulse in `dealerMaterials()` is a slow swell and a faint breath, not a flash). The Black Jack's end draws the camera back to the cleared tables' high framing and lets its cards (materials `transparent` from build), lettering and gold lamp go dark as the page's card comes up. The blackjack's odds read 4.8%, the natural's real two-card rate (`tierOdds`). The cloth is lifted a step (near-black; a warm dark brown for The Black Jack, so the gold light has something to pick up), and a second, softer pendant pool with no shadow lifts its middle tones. The print's rule lines are set smaller (`LETTERS` caps 1.0 and 0.5). Beside that pool a broad 14000-candela warm fill (`goldFill`, built with the lamp, the same envelope) spreads over the felt and rail, so the table reads gold in the payout and not a black field. A phone's lens stands back further (`W2` 1.3 when `tall`) so the rule line and the plates sit inside a narrow frame. Each finger carries a graphite pin across each joint (`pin()` in `buildDealerHand()`). Under The Black Jack's 9000-candela lamp the bet chips (the stake stack: ivory, oxblood, gold, always held a little under full exposure) and the payout chips (gold, onyx, oxblood: no ivory) are held down in exposure and made matte while it is up (`payout.expose()` lerps material colour, roughness and metalness only, so nothing compiles mid-shot), or the gold clips to cream. ## Cloud Sync

- **On by default, opt-out.** `isSyncEnabled()` reads the enabled key against the literal string `'false'` - an unset key (fresh install) is enabled. `initSync()` runs at boot regardless of the landing screen and signs the device into an anonymous Supabase account automatically (`ensureSyncSignedIn()`), no button click required; `dismissLanding()` also kicks a sync attempt for immediacy. The Settings toggle (`toggleCloudSync()`) is the opt-out, not the opt-in - don't revert this to "disabled by default" without discussion, that was a deliberate later change from the original opt-in design.
- Client code lives in the "Cloud sync" block in the inline script in [index.html](index.html) (search for `SUPABASE_URL`); server schema is the `collection_events` table in the Supabase project (`ewfvyrhlsanzkmozrmhs`) managed via migrations applied through the Supabase MCP tools, not a checked-in `.sql` file - use `list_migrations`/`execute_sql` against that project to inspect it. The `id` column is `text`, not `uuid` - it holds the app's own `uid()`-style ids (e.g. `id_yar7dm8yd`), not real UUIDs; this was a real bug once (every push 400'd) before the column type was fixed to match.
- It's an outbox-and-replay design over `collectionHistory` only (the ledger behind streaks/stats - not `trackedGames`, not settings): local mutations enqueue an op via `enqueueHistorySync(entry, deleted)` (a no-op while sync is disabled), `flushSyncOutbox()` pushes it (upsert by id), `pullAndReplay()` fetches rows changed since the last cursor and applies them locally by id, tombstoning (`deleted: true`) rather than hard-deleting so other devices learn about removals instead of resurrecting them. `kickSync()` is the shared "try now" entry point (seed-if-needed + flush + pull) used by every automatic trigger; `initSync()` sets up the recurring interval/listener exactly once and must not be called more than once per page load.
- Every `collectionHistory` entry needs a stable `id` (assigned by `ensureHistoryEntryIds()` on load, and inline wherever a new entry is created) for this to work - preserve that if you touch collection-history code, even when sync itself isn't what you're changing.
- The anon/publishable key in `index.html` is meant to be public (protected by RLS, not secrecy) - don't treat it as a secret to scrub, but also don't add anything there that would need to be one.
- Browser roles start with nothing: the `least_privilege` migration revoked the default table grants from `anon`/`authenticated` and changed the default privileges, so a new table or RPC is unreachable until its migration says `GRANT` explicitly. Views are `security_invoker`; a public view needs a published-row policy and column grants on its tables, not `SECURITY DEFINER`.
- The catalogue's own RPCs (`get_catalog`, `publish_catalog`, the owner's reports) live in the `catalog_service` migration. Merging a [data/catalog.json](data/catalog.json) change to `main` publishes it through the Publish catalogue workflow; a branch alone changes nothing users see.

### Email linking (device-independent recovery)

- Anonymous auth alone has no credential to sign back in with elsewhere - clearing a device's storage loses local access to that device's cloud copy. Email linking closes that gap: `linkEmailToAccount()` attaches an email to the CURRENT (anonymous) account via `client.auth.updateUser({ email })` - same user id, same data, now with a credential. `sendRecoverySignIn()` is the opposite direction - pulling a previously-linked account's data onto a new/wiped device via `client.auth.signInWithOtp({ email, options: { shouldCreateUser: false } })`. `shouldCreateUser: false` is load-bearing: without it, recovering with an email that was never linked to anything would silently create a new blank account instead of failing, which would look like recovery while doing the opposite. Keep that flag.
- Both flows use passwordless email links, not passwords - no password field exists anywhere in this UI, and none should be added without discussion.
- `getEmailRedirectTo()` resolves to `window.location.origin + window.location.pathname` at call time - no hardcoded production URL, since there's no build step to bake one in and the app also runs on GitHub Pages subpaths, custom domains, and localhost. This only works if that exact resolved URL (or a matching wildcard) is in the Supabase project's Auth "Redirect URLs" allow list (dashboard, not available via any MCP tool here) - if email links stop completing after a domain change, check that list first, not the code.
- `getSupabaseClient()` registers a single `onAuthStateChange` listener (fires on the routine anonymous sign-in too, not just an email link completing) that repaints the email section and kicks a sync attempt - don't register a second one elsewhere, and don't call `initSync()` more than once per page load for the same reason `kickSync()`'s interval/listener setup already warns about above.
- `renderSyncEmailUI()` distinguishes a linked account from anonymous via `session.user.is_anonymous` - an anonymous session still has RLS access (`authenticated` role either way), so this is a display/UX signal, not a security boundary; don't repurpose it as one.

### First-collect email gate

- `markCollected()`, `collect()`, `collectCurrentDailyRun()`, and `openDrop()` (only when it would actually log a collection) each open with `interceptForEmailGate(retryFn)` - a synchronous check against `cachedHasLinkedEmail`/`EMAIL_GATE_PASSED_KEY`, not an async session lookup, since these are synchronous `onclick` handlers. If it returns `true` the caller must return immediately without doing any of its own work; `retryFn` is what re-runs the original action once the gate clears, so add the check to any NEW function that logs a collection the same way, and keep it a closure over the same args the original call had.
- `collectCurrentDailyRun()` is gated at its own level even though it calls `collect()`, which is also gated - `collect()` bailing out on its own wouldn't stop the daily-run wrapper from still advancing `dailyRunIndex`/stats as if the collection had happened. Any future wrapper around a gated function needs the same double-gating, not just the inner call.
- The gate only requires *submitting* an email (`linkEmailCore()` resolving, i.e. the confirmation email queued), not waiting for the confirmation click - that's a deliberate friction tradeoff (chosen explicitly over a harder "block until confirmed" gate and a softer "just nag, never block" one), not an oversight. Don't tighten it to wait for confirmation, or loosen it to a dismissible reminder, without discussion.
- Browsing, adding/removing platforms, and every non-collecting action stay completely ungated - only actions that call `logCollection()` (directly or via the functions above) are.
- Canceling the gate (`cancelEmailGate()`) must never let the pending action through - it only clears `pendingGatedAction` and closes the modal. There is no bypass path; verify this stays true if this code is touched.

- Avoid reformatting unrelated sections.
